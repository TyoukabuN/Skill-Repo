# 创建代码解释文档

以实际源码为依据，把代码如何工作写成可独立阅读、可追溯的技术文档。沿用项目已有的语言、文档结构和命名约定；没有约定时使用用户当前交流的语言。

## 确定输出位置

- 用户已指定文件或目录时，直接使用该位置，不重复询问。
- 未指定时，先阅读适用的项目指令，并检查已有文档、入口链接和目录结构，沿用与目标模块对应的文档位置。
- 找不到明确约定，或有多个无法判断的候选位置时，简短询问用户。在等待答复期间可以继续查阅代码和整理提纲，但不自行创建文档目录。
- 不预设固定目录名，不把本机绝对路径、某个仓库的结构或本技能的安装位置当作文档输出位置。
- 用户仅要求查询文档覆盖情况时，先返回查找结果和相关位置；未要求补充时不修改文件。

## 分析与写作流程

1. **先查现有文档**：优先用 `rg` 搜索模块名、符号名和相关概念，区分已有说明、缺失内容和已过时的说明。
2. **阅读相关实现**：从入口追踪关键调用、数据流、状态变化和组件职责。需要时检查配置、序列化资源、测试及调用方，避免只根据类名或注释推断行为。
3. **选择修改位置**：已有文档覆盖同一主题时优先补充或修正；独立的新主题再单独建文件，避免重复说明。
4. **编写文档**：先说明职责与边界，再按执行顺序解释流程及关键实现。区分已核实的代码行为、设计意图和推测；无法确认的内容明确标注。
5. **维护导航**：沿用已有索引、README、侧栏或其他文档入口。仅在新增内容需要入口且项目没有约定时创建适量索引，不强制每个目录都有索引。
6. **核对结果**：检查路径、符号、代码片段、流程顺序、Markdown 链接和章节导航，确保说明与当前实现一致。交付时说明创建或修改了哪些文档，以及仍待确认的事项。

## 写作规范

- 使用短章节和具体语言，每章聚焦一个问题，能独立理解。避免“以下将介绍”等空话。
- 相关限制、前提和异常行为融入对应流程，不额外堆积泛泛的“注意事项”。影响执行结果的错误处理和边界条件不能为了简短而省略。
- 默认将单篇控制在约 300 行以内；内容较多时按独立关注点拆分，并通过项目现有导航串联。已有规范或用户要求优先，不为满足行数机械拆分。
- 调用链可以使用缩进伪代码；实现片段使用与实际语言对应的代码块标识。代码仅保留解释所需部分，并标明省略处或伪代码，避免让读者误以为片段可直接运行。
- 源码引用使用项目中可解析的路径或相对链接，并附关键符号名；必要时添加行号。可迁移文档不写作者机器的绝对路径。
- 架构图、流程图和职责表按解释需要添加，不要求每篇套用全部结构。

## 可选结构

按主题选择和调整下列章节，简单主题可以合并；不相关的章节直接省略。

```markdown
# 模块名 — 一句话说明

一两句话说明文档覆盖的职责、入口与边界。

## 核心概念与结构

解释主要对象、依赖关系和数据来源。

## 关键执行流程

按执行顺序说明入口、调用关系、状态变化及输出。

## 关键实现与边界条件

结合精简源码解释实现选择、前提条件和异常路径。

## 组件职责

| 组件或符号 | 职责 | 源码位置 |
| --- | --- | --- |
```

## 多文件导航与编辑

- 同一主题拆为多篇且存在阅读顺序时，在标题下方和文末添加上一章、返回目录、下一章的相对链接；首尾章节省略不存在的链接。
- 链接目标和索引文件名取自实际文档结构，不假定存在特定名称的索引文件。文末导航可用分隔线与正文分开。
- 导航符号沿用项目风格，无约定时使用简洁文字。无需将某种字符或操作系统的历史替换问题设为通用禁令。
- 编辑时使用当前环境可用的精确补丁工具，例如 `apply_patch`；限定修改范围并检查差异，避免无关的目录级批量替换。不依赖特定编辑器的专用命令。
